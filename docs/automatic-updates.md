# 자동 갱신과 복구

PC·Chrome·ChatGPT를 켜둘 필요 없이 GitHub Actions에서 실행한다.

| 대상 | 한국시간 평일 실행 시각 |
| --- | --- |
| 기존 커버리지 | 18:20, 19:20, 20:20 |
| KOSPI200·KOSDAQ150 | 18:35, 19:35, 20:35 |

`FLOW_AUTO_UPDATE=true`가 예약 실행 조건이다. GitHub 예약 자체가 늦어질 수 있으므로 위 시각은 보장된 시작 시각이 아니다. 같은 데이터 저장 작업은 `flow-data-update` 그룹으로 직렬 실행하며 `queue: max`로 대기 작업 교체를 방지한다.

각 실행에서 인증된 KRX KOSPI 조회로 최신 실제 거래일을 확인한다. 저장된 수급·가격 파일의 meta.as_of와 각 상태 파일의 as_of가 모두 일치하고, 누락/실패가 없으며, 공시 조회까지 당일 성공했으면 이후 예약에서는 전체 수집을 생략한다. 수동 실행은 전체 수집한다. 코드 변경(push)에서는 기존 방침대로 공시 전체 조회를 생략한다.

최신 KRX 응답이 평일의 이전 거래일이면 휴장과 제공 지연을 임의로 구분하지 않는다. `closed_or_provider_delayed` 경고를 남기고 이후 슬롯에서도 다시 조회한다. 기준 거래일 조회 실패나 저장 파일 불일치, 수급 누락, 공시 일부 실패는 작업을 실패 처리한다. 실패 원인은 Actions annotation·Summary와 `dist/data/index-update-monitor.json`, `legacy-update-monitor.json`에 기록한다. 개별 수집 오류가 있어도 나머지 수집/검증을 계속하고 마지막에 실패를 보존한다.

이전 거래일에 캐시된 벤치마크가 재시도 결과를 가리지 않도록 KOSPI 거래일 조회는 캐시를 재사용하지 않는다. 검증된 원본을 가상 데이터로 대체하지 않는다.

별도 이메일·메신저 알림을 생성하지 않는다. GitHub 실패 알림 수신 여부는 계정의 Actions 알림 설정에 따른다. 세 예약이 모두 GitHub에서 발생하지 않는 장애는 같은 GitHub 예약만으로 감지하거나 복구할 수 없다. 독립적인 보장이 필요하면 Cloudflare Cron 같은 외부 감시와 GitHub workflow_dispatch 호출을 별도로 연결해야 한다. 이 외부 연결은 아직 구현하지 않았다.
